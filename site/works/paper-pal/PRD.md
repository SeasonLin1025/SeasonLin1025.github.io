# Paper Pal · 论文阅读伴侣

> 把"找论文 → 读论文 → 记笔记 → 写综述 → 引用"五段式割裂工作流，
> 收敛进一个 AI 原生工作台。

**版本**：v0.1 PRD（草案）
**作者**：林熙哲
**目标用户**：自己 + 高校研究生 + 跨学科学习者
**最后更新**：2026-05-10

---

## 0. 一句话定义

**Paper Pal 是一个"读完一篇论文只要 5 分钟、读完一个领域只要一周"的 AI 论文工作台。**

它不是又一个 PDF 阅读器，也不是又一个翻译插件——它是把"论文消费 → 知识沉淀 → 学术输出"完整链路用 AI 串起来的**个人知识引擎**。

## 1. 痛点画像（Why now）

### 1.1 真实场景（来自我自己）

我是武大土木硕士、目标 AI PM。每天我要：

| # | 场景 | 现状痛苦 | 平均耗时 |
|---|------|----------|----------|
| 1 | 看 arXiv 推送 / 导师群的英文论文 | 复制摘要 → DeepL → 看不懂术语再问 ChatGPT | 20 分钟/篇 |
| 2 | 决定一篇论文要不要精读 | 全靠"标题 + 摘要"赌博，常常读到第 4 页才发现走错方向 | 30 分钟成本 |
| 3 | 整理笔记 | Notion / Obsidian / Word 三个地方各存一点，找不到 | 检索耗时 ↑↑↑ |
| 4 | 写文献综述 | 把 30 篇笔记拼起来，反复对比"谁说的更全面" | 2-3 天 |
| 5 | 引用格式 | EndNote 不好用，手动改 BibTeX 易错 | 5 分钟/条 |

### 1.2 现有方案为什么不够

| 工具 | 解决了什么 | 没解决什么 |
|------|------------|------------|
| ChatPDF / Humata | 单文档 QA | 跨文档对比、知识沉淀、引用管理 |
| Zotero | 文献管理 + 引用 | AI 理解、自动总结、提问 |
| Notion AI | 笔记智能化 | 不读 PDF、不理解学术语境 |
| Connected Papers | 论文关系图 | 不读内容、不沉淀笔记 |
| 翻译插件（沉浸式翻译等） | 翻译 | 不总结、不沉淀、不提问 |

**Paper Pal 的差异化定位**：
> **"读"+"问"+"沉淀"+"输出" 一站式。** 单文档场景不输 ChatPDF，跨文档场景没人做过。

### 模块二：🧠 智能解析（Understand）

## 5. 技术架构（MVP 静态站方案）

> **目标**：纯前端 + 用户自带 API Key，零后端、零成本，部署到 GitHub Pages。

```
浏览器
├── PDF.js                  → 解析 PDF 文本 + 渲染
├── pdfjs.getDocument(...)
│
├── Compromise / Tiktoken   → 切片文本 + 计算 token
│
├── 向量化（轻量本地方案）
│   • 短文档：直接全文塞进 prompt（128k 模型够用）
│   • 长文档：调 OpenAI embeddings → IndexedDB 存向量 → 余弦相似检索
│
├── LLM Client
│   ┌─ OpenAI (gpt-4o-mini)
│   ├─ DeepSeek (deepseek-chat) ← 默认推荐，便宜
│   ├─ 通义 / 智谱
│   └─ Ollama (本地)
│   ↑ 用户在设置里粘贴自己的 API Key
│
├── 存储
│   • IndexedDB → PDF 文件 + 解析结果 + 笔记 + 向量
│   • LocalStorage → 用户配置
│
└── UI
    • 原生 HTML/CSS/JS（保持 vibe coding 风格，与现有作品集技术栈一致）
    • 或 React + Tailwind（v0.2 升级）
```

**关键技术决策**：

1. **API Key 用户自带（BYOK）** —— 解决账单 + 隐私 + 合规
2. **数据全本地** —— 论文不上传任何服务器，比 ChatPDF 更安全
3. **离线可读** —— 上传过的论文，断网也能查、能问（缓存 embedding 即可）
4. **可选云同步** —— v1.0 用 Supabase / Vercel KV，按需启用

| 风险 | 等级 | 缓解 |

## 附录 B · 关键提示词模板（v0.1）

### B.1 三句话精华
```
You are an expert research assistant. Given the following paper text, output exactly 3 sentences in Chinese:
1. What problem does this paper solve?
2. What is the core method?
3. What is the most surprising finding or main result?
Keep each sentence under 50 Chinese characters. Avoid jargon.
```

### B.2 PM 视角解读（差异点）
```
You are a senior product manager. Read the following research paper and reframe it as if it were a product brief:
- Background (the "user pain")
- Target user / scenario
- Core "feature" (the method)
- Quantitative success metric (the experiment results)
- Risks & limitations
Output in Chinese, Markdown bullet list, total ≤ 200 characters.
```

### B.3 跨文档对比
```
You are an expert reviewer comparing N research papers. For each paper, you have its structured summary.
User question: {user_question}
For your answer:
1. Explicitly compare papers side-by-side using a Markdown table when appropriate.
2. For every fact, cite [Paper #N, page X].
3. End with a concise verdict (≤ 2 sentences).
```
